# 口播稿生成与质量策略

AI 简报和财经口播使用同一套 `plan → draft → repair` 服务。计划阶段只选择并编排事实；成稿阶段只执行经过校验的计划；修复阶段根据确定性的质量问题做最小修改。事实包是数据，不会执行其中的指令。

`script_generation/policy.py` 是口播稿的唯一策略源。当前版本为 `script-quality-v7`：AI 简报硬范围为 350–500 字、推荐 380–450 字；财经硬范围为 300–600 字、推荐 400–450 字。推荐范围只记录审计结果，不会阻断人工审核稿。

AI 简报采用数字优先强钩子：已选事实存在模型参数、金额、数量、百分比等有信息量的来源数字时，首句必须使用其中量级最大、反差或结果感最强的一个，放在前 12 个字符内，并紧接主体和明确动作。首句控制在 12–28 字，最多一个核心数字；日期、时间和序号不算钩子数字，也不能代替业务数字。数字缺失会阻断生成；数字后置或首句过长会产生告警并送入定向修复。没有有信息量数字的事实不要求编造数字。

强表达必须服务于来源事实。AI 简报中的“炸裂”“颠覆”“封神”等只在事实包有同义评价、比较或极值信息时使用；没有这类来源支撑时，可用“直接”“一下推到”“很猛”等较轻的口语节奏，但不得把行业影响、绝对领先或性能结论写成事实。财经稿可主动使用“炸裂”“封神”“颠覆”“跳水”“硬拉”“杀跌”“被砸”等高张力口播词，但必须在同句或相邻句绑定来源给出的单日行情主体、方向、数字和单位；它们只能强调已发生的行情，不能变成趋势预测、见底或牛市判断、收益承诺或买卖/加减仓建议。财经首句必须先给出这一可核验行情锚点，日期和栏目背景后置。原有状态和归因边界仍必须保留。

质量校验会阻断素材外数字、AI 状态升级或归因遗漏、财经主体/数值/方向/单位错绑、交易指令、Markdown、文件路径和格式损坏。财经稿必须包含风险提示及“不构成投资建议”。系统只保证成稿不超出上游素材，不保证上游来源本身真实。

## 质量门禁 strict 与 soft

`quality_gate` 是 AI 简报与财经共用的任务参数，默认 `soft`，同时作用于口播稿校验和标题/描述校验，`strict` 完全保留旧行为。

- `soft` 执行同样的检查，但把非合规问题记为告警，不再让任务失败；问题本身、证据和代码照旧写进 `script/quality-report.json`、`metadata_audit.json` 和任务事件，只改变阻断与否。
- 仍会阻断的合规集合：口播稿的 `finance_prohibited`、`finance_disclaimer`、`finance_risk_warning`（面向观众的交易指令、免责声明、风险提示），以及标题/描述的 `empty_text`、`fact_anchor_missing`、`script_anchor_missing`（空文本、未锚定素材或口播）。其余检查（包括字数、Markdown、格式、素材外数字、状态升级、归因、精准用词）默认只告警；新增检查默认走 soft，不需要逐个登记。
- 两个质量报告都新增 `gate` 字段，可据此区分“真正通过”和“因放宽而通过”。标题字符上限属精准检查，下游仍会按 `build_publish_title(max_chars=16)` 截断。
- 内容工作台的人工审核稿固定使用 `strict`（`reviewed` profile），它是人工核对入口，不是无人值守任务。

审计保存内容专项和阶段版本、质量策略版本、模型名、系统与用户提示词的 SHA-256 指纹，以及推荐长度命中情况。事件日志只保留版本、指纹、阶段和问题代码，不记录完整提示词、正文或凭据。

## AI 简报与财经的标题、发布描述

仅 `ai_briefing` 和 `finance` 增加独立的标题、描述阶段，顺序为：素材 → 合格口播 → 标题 → 发布描述 → 封面/视频 → 原有可选发布。标题和描述基于结构化素材与最终口播生成，描述还可使用最终标题；它们不是口播生成调用附带的输出，不改变内容工作台或其他管道。

- `title_writer`、`description_writer` 均支持 `follow_script`、`rule`、`llm`，默认 `follow_script`，分别跟随 `script_writer` 的实际配置模式；也可独立选择规则或大模型。
- 非空 `params.title` / `params.description` 是手动覆盖，优先使用并跳过对应生成阶段，另一个留空字段仍按自己的模式生成。任务顶层的 `description` 是任务说明，不是发布简介。
- 两类管道的发布描述默认改为空，以启用自动处理。`rule` 模式保留原固定简介：AI 为“今日AI简报”，财经为“每日基金日报，仅供参考，不构成投资建议”。旧任务、定时任务、默认参数覆盖或浏览器记忆中仍有非空简介时，会继续作为手动值；要启用自动描述，必须显式清空。
- `metadata_failure_policy` 默认 `fail`：标题或描述失败会阻断媒体制作与后续发布，不会静默回退。显式选择 `validated_rule_fallback` 才允许回退，且规则候选同样必须通过校验。`metadata_repair_attempts` 为每个生成阶段的修复上限，允许 0–2，默认 1。`quality_gate` 默认 `soft`：标题与描述的非合规问题只记告警，空文本或不锚定素材/口播仍会阻断，详见下文“质量门禁”。

大模型标题须为单行纯文本，以 8–16 个字符为目标、含内部空格和标点上限 16 个字符；自动描述以 60–150 字为目标、上限 300 字。规则及已校验规则回退保留 AI handoff 的完整标题、财经的“每日基金日报 · YYYY-MM-DD”标题，再沿用原下游长度适配，不套用大模型的 16 字硬限（规则标题仅设 2000 字保护上限）。检查包括事实引用、素材外数字、确定性升级和收益承诺；财经大模型描述须有风险提醒与“不构成投资建议”。规则模式保留简短固定简介，不强制扩写至推荐长度；财经旧固定简介的“仅供参考”兼容保留并记录告警。手动标题继续沿用原有各目标长度适配，不自动改写人工文案；手动文案不做自动事实校验。确定性检查不能完全保证语义真实性，发布前仍需人工核对来源、口播和最终文案。

任务目录的 `metadata_audit.json` 汇总标题和描述结果，`title_audit.json`、`description_audit.json` 分别保留已执行阶段的最终文本、来源（手动/规则/大模型/回退）、质量检查与尝试审计；失败也保留可排查的审计产物，外部调用错误只记录脱敏摘要。可在任务产物与事件中检查这些阶段，不能只以视频存在判断文案生成成功。

`dry_run: true` 仅让媒体与发布走干运行；口播、标题或描述解析为 `llm` 时仍会真实调用已配置的大模型，产生费用并发送素材及口播文本。需要完全离线验证时，将三个 writer 都设为 `rule`（或令两个元数据 writer 跟随规则口播），并保持 `publish: false`。

代码更新不会自动使长期运行的后台进程加载新阶段；验证通过后仍需另行部署并重启后台。文档与默认模板更新不等于修改或启用现有项目定时任务，生产任务迁移应另行受控进行。

## 内容策略实验

财经任务默认使用 `strategy_profile=finance_conversion`，AI 简报默认使用 `strategy_profile=ai_reach`。实验任务可设置 `experiment_id` 并选择 `script_mode=short_30_60` 或 `script_mode=long_1_3_minutes`；旧的 `90_seconds` 任务继续使用原有字数和时长行为。

`finance_conversion` 要求开头尽快说明行情影响对象，并在结尾给出持续关注理由；`ai_reach` 要求标题和开头优先呈现具体公司或模型、明确结果及影响。实验参数会写入脚本审计和 MoneyPrinterTurbo 生成清单。

发布后的平台数据可以导入本地分析库：

```powershell
uv run python scripts/performance_metrics.py import --input .\metrics.xlsx
uv run python scripts/performance_metrics.py summary
```

导入支持 `.xlsx`、`.csv` 和 `.json`，摘要按内容线、时长版本和平台计算播放、互动率及涨粉/千播。导入只保存用户提供的平台统计，不自动调用平台接口。

## 内容工作台与离线评估

内容工作台的自动生成稿使用 `generated` profile；人工审核稿使用 `reviewed` profile，推荐/硬字数只告警，但文件路径、占位内容、财经风险提示、免责声明和交易安全仍会阻断视频生成。

离线评估默认只校验固定语料，绝不调用 LLM：`uv run python scripts/evaluate_script_prompts.py validate`。结果写入被忽略的 `output/prompt-evals/`。`generate` 与 `compare` 目前会明确拒绝执行，等待后续接入一个显式配置的离线 runner；真实 LLM 或 TTS 验证应单独受控执行，不能改变项目内置定时任务配置。
